# 移动端与响应式检查清单（C · 视觉）

测量时间：2026-11-11 · 对象：当前工作区版本

## 结果总表

检测方式：CDP 设定视口 → 加载 → 逐元素量 `getBoundingClientRect()`，判定标准是「右边界超出视口 / 左边界为负 / 下边界超出视口」；同时查 `documentElement.scrollWidth`。

| 视口 | 尺寸 | 横向滚动 | 元素出界 | 结论 |
|---|---|---|---|---|
| 手机小屏 | 375 × 812（DPR 2） | 无 | 0 处 | 通过 |
| 手机常规 | 390 × 844（DPR 2） | 无 | 0 处 | 通过 |
| 平板竖屏 | 768 × 1024 | 无 | 0 处 | 通过 |
| 手机横屏 | 812 × 375（DPR 2） | 无 | 0 处 | 通过 |
| 开场页 | 375 × 812 | 无 | 0 处 | 通过 |
| 第 7 屏（含三问） | 375 × 812 | 无 | 0 处 | 通过 |
| 2D 降级 | 375 × 812 | 无 | 0 处 | 通过 |

`scrollWidth` 四个视口都等于 `innerWidth`，没有横向溢出。

## 已修过的问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 第 7 屏「重新看一遍」被挤出视口（bottom 856 > 812） | 加了「三问」后面板变高 | 窄屏收紧间距 + 面板内滚动兜底，现在 bottom 790 |
| 开场页按钮和 3D/2D 开关挤在同一行 | `.intro-mode` 是 `inline-flex` | 改成 `flex` + 居中，单独一行 |

## 仍需注意（未处理）

1. **3D 第 5 屏水面在软渲染下几乎不可见** —— 水面只有 0.5 单位厚、透明度 0.5，被暖光吃掉。真机 GPU 上会好一些但仍然偏弱。属于水面材质问题，不是布局问题。
2. **第 3 屏相机是正对的** —— 两块板占满画面，剖面没有层次，手机上看尤其像“两块木头”。建议改 3/4 视角。
3. **第 6 屏术语墙偏长** —— 词条多时面板接近满屏，375 宽下需要滚动才能看完。
4. **真机未测** —— 本表全部是 headless 模拟视口，没有覆盖 iOS Safari 的地址栏收缩、滚动惯性、字体渲染。这部分必须真机走一遍。

## 真机检查步骤（需要人做）

1. iOS Safari + Android Chrome 各打开一次
2. 从头滚到尾：有没有卡顿、地址栏收起时进度条会不会跳
3. 第 7 屏：三题能否点、按钮是否够大（建议 ≥ 44px 命中区）
4. 横屏：转一下，看面板是否被裁
5. 系统开「减少动效」再走一遍

## 2026-11-16 复测（3D 全量合入 main 之后）

检测方式换成脚本化的 CDP 审计：设视口 → 触发开场 → 滚到指定屏 → 量
`scrollWidth`、逐元素 rect、按钮命中高度，并同时截图。脚本在
`outputs/mobile-audit2.mjs`（不进仓库）。判定加了「祖先可滚动则不算出界」，
否则文案面板内部滚动的内容会被误报。

| 视口 | 开场页 | 第 5 屏 | 第 7 屏 | 横向滚动 |
|---|---|---|---|---|
| 375 × 812（iPhone SE，DPR 2） | 通过 | 通过 | 通过 | 0 |
| 812 × 375（横屏） | 通过 | 通过 | 通过（面板内滚动） | 0 |
| 768 × 1024（iPad 竖屏） | 通过 | 通过 | 通过 | 0 |

### 这轮修掉的

| 问题 | 实测 | 处理 |
|---|---|---|
| 横屏开场页溢出 | `.intro-inner` 底边 389 > 375，3D/2D 开关被切 | 新增 `max-height:520px` 断点，字号间距各压一档 |
| 第 7 屏选项被截 | `.quiz` 底边 833 > 812，第三题要滚才看得到 | 窄屏 `body[data-beat='b7'] .copy` 放开到 62svh |
| 横屏宽屏面板出界 | 走桌面样式无 `max-height`，面板长到视口外 | 矮视口统一 `calc(74svh - safe-area)` + 面板内滚动 |
| 命中区偏小 | 选项 31–35px、回看 39px、语言按钮 26px | 按 `pointer:coarse` 统一到 44px / 40px |

### 仍未能覆盖

- **iOS Safari 真机**：`svh` 与地址栏收缩、惯性滚动、底部安全区，模拟器只能近似。
- **Android Chrome 真机**：字体回退与触控延迟。
- **减弱动效**：`prefers-reduced-motion` 只做了代码路径检查，没在真机开系统开关验证。

这三项必须由人拿真机走一遍，见上节「真机检查步骤」。
