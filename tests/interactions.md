# 交互手工用例（B · 20 条）

> 环境：Chrome 桌面 + iOS Safari + Android Chrome。
> 每条记录「预期 / 实际」，实际不符就当场修，修完重跑本组。

## 一、补缝三步（b3）

| # | 操作 | 预期 | 实际 |
|---|---|---|---|
| 1 | 依次点 榫卯 → 铁钉 → 捻缝 | 三步亮起，缝闭合，出现「重来」 | |
| 2 | 点 铁钉 打头 | 提示「顺序不对」，只闪错，不清空已有步骤 | |
| 3 | 错误后等 1 秒 | 提示自动消失，已亮步骤保持 | |
| 4 | 完成后看三个按钮 | 全部 disabled，`aria-disabled=true` | |
| 5 | 点「重来」 | 回到初始态，「重来」隐藏，焦点落在第一个按钮 | |
| 6 | 完成态按 Tab | 不会卡在被 disable 的按钮上，能到「重来」 | |
| 7 | 快速连点 捻缝 5 次 | 只入栈一次，不重复推进 | |
| 8 | 触屏上点按钮 | 命中区 ≥ 44px，不误触相邻 | |

## 二、漏水实验（b5）

| # | 操作 | 预期 | 实际 |
|---|---|---|---|
| 9 | 点「无隔舱」 | 水面漫过全船，船下沉 8 单位，1.2s 内收敛 | |
| 10 | 转场中点「有隔舱」 | 不立即跳，收敛后再执行，最终是有隔舱 | |
| 11 | 连点 5 次「无隔舱」 | 结果与点 1 次一致，不叠加 | |
| 12 | 同一状态再点一次 | 从头重播，不卡在中间态 | |
| 13 | 读屏打开 | 状态变化被播报（role=status） | |
| 14 | 触屏点两个按钮 | 命中区 ≥ 44px | |
